# Rpi5Display 0.1.8 — Lab Candidate

> **Current development candidate: 0.1.8. Known-good hardware baseline: 0.1.7.**
>
> The 0.1.7 framebuffer/display-only path has reached a working Windows desktop on the Raspberry Pi 5. Version 0.1.8 keeps that present path and adds validated firmware timing/EDID metadata. The 0.1.8 physical timing/EDID result is still the next hardware gate. A green hosted build is not a passed Pi test.

## What is included

This pre-release provides a ready-to-extract **CMD installer** for Windows 11 ARM64 on Raspberry Pi 5. The package includes:

- `Install.cmd` — validated, interactive installer entry point
- `Preflight.cmd` — read-only prerequisite and platform checks
- `Collect-Logs.cmd` — diagnostic/support bundle capture
- `Uninstall.cmd` — verified package removal path
- test-signed ARM64 `Rpi5Display.sys`, INF, CAT and lab certificate
- package pinning, source snapshot, symbols and diagnostic scripts

The installer requires an explicit `INSTALL` confirmation and does not automatically reboot, flash firmware, disable Secure Boot/Memory Integrity, change BCD, or upload logs.

## 0.1.8 changes

- Preserves the hardware-working 0.1.7 `PresentDisplayOnly` framebuffer/copy path.
- Consumes the paired UEFI exp0.7 volatile `Rpi5DisplayHandoff` runtime variable.
- Validates variable attributes, signature/version/size, exact POST geometry, progressive timing, pixel clock/totals and complete EDID checksums.
- Returns validated monitor EDID through `DxgkDdiQueryDeviceDescriptor`.
- Reports firmware-derived pixel clock, HSync/VSync and totals in VidPN signal information.
- Falls back to the 0.1.7 unspecified-timing behavior if the firmware handoff is absent or invalid.
- Does **not** add native HVS/HDMI mode setting, V3D/Direct3D acceleration, hardware cursor, interrupt-driven VSync, or multiple-output support.

## Installation

Use a restorable test Windows image and keep independent recovery access available.

1. Download `Rpi5Display-0.1.8-CMD-Installer.zip` and `SHA256SUMS.txt` from this release.
2. Verify the ZIP SHA-256.
3. Extract the **entire ZIP** into a new local folder on the Windows Pi.
4. Run:
   ```cmd
   Install.cmd
   ```
5. Review the preflight output and type `INSTALL` only when you are ready to proceed.
6. Keep the generated support ZIP after installation and hardware testing.

The test Windows installation must already be configured to allow test-signed kernel drivers. Follow Microsoft test-signing guidance rather than bypassing signature checks.

## Required 0.1.8 hardware gate

Test with the paired Raspberry Pi 5 UEFI exp0.7 candidate and keep the exp0.6 + driver 0.1.7 baseline available for recovery.

Do not call 0.1.8 hardware-validated until the physical Pi confirms:

- display device remains Started / ProblemCode 0;
- the Windows desktop remains visible and usable;
- Advanced Display shows a numeric refresh rate instead of `Unknown`;
- the connected monitor's checksum-valid EDID is exposed;
- reported pixel clock/totals derive to the displayed refresh;
- invalid/missing handoff falls back to the 0.1.7 behavior without losing the desktop;
- Wi-Fi, fan/temperature, NVMe, microSD and USB remain healthy.

Only after those checks should TestUFO/MotionMark be used as timing/performance evidence.

## Status

**Pre-release / experimental lab driver. Not production-qualified. Not yet physically validated for the new 0.1.8 timing/EDID path.**
